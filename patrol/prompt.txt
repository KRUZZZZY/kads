Useful background (not a checklist):
- Commands are registered in a ControlRegistry and reached over a JSON-RPC socket, Lua and MCP; mutating commands should leave exactly one undo step (ProjectJournal) and their reversibility row should be honest.
- Every command's arguments are validated against its declared argsSchema BEFORE the handler runs (ControlRegistry::invoke -> validateArgs): a wrong type, a fractional value for an integer field, a missing required field or an out-of-range enum never reaches the handler. Report an argument bug only where the schema cannot catch it (an untyped array/object field, a value the schema allows but the handler mishandles, or data read from a project file).
- Realtime rule: nothing on the audio thread (process/render paths, play handles, mixer channel processing, anything called per period) may allocate, lock a mutex, log, or touch Qt objects that allocate.
- Ids and indices start at 0, so 0 is not a usable "none" sentinel; f_cnt_t / tick-like types may be unsigned, so -1 sentinels on them are bugs.
- Qt 6: a default-constructed QJsonValue is Null, not Undefined; a QDomElement not appended to its document serialises to nothing; deleteLater'd widgets linger until the event loop runs.
- tick_t is std::int32_t (signed); project journal ids always carry the high bit, so 0 is never a real id; a cloned Clip adds itself to its track in Clip's copy constructor; slots is a Qt macro.
- Known by design, do not report: the append-only <z:provenance> save journal; undo coalescing and 'undone_commands'; mastering.run's async acknowledgement; boolean param_set refusing fractions; first save reported reversible:false; empty-active tempo-map persistence; fx-id renumbering after removal; id:-1 replies to malformed wire messages.
